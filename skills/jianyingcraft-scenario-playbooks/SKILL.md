# JianyingCraft 场景剪辑手册

场景技能决定**为什么这么做、先做什么、参数怎么选、做到什么程度、怎么判断结果**；
执行由 JianyingCraft 派生引擎（filmcraft 0.8.0 的 165 条命令面）完成。

## 铁律：先发现，再执行

命令 id 一律来自运行时，不得凭记忆写：

```
command_list {"filter": "timeline"}      # 找切分/移动/放置
command_list {"filter": "caption"}       # 找字幕相关
command_list {"filter": "export"}        # 找导出与队列
```

返回里看 `id`、`params`、`enabled`。**遇到找不到的命令就停**，报告缺什么能力，
不要用相近命令硬凑——那会产出"看着成功、结构是错的"工程。

## 共同结构

1. **诊断**：`project_inspect` + `sequence_inspect`，确认素材、时长、画幅、目标交付。
2. **选后端**：用户要看着改 → 可见面板（`craft_submit`）；只要出片 → `jianyingcraft-cli mcp` 无头。
3. **执行**：按下面的序列走，每步用 `sequence_inspect` 核对结构，不只看命令是否 ok。
4. **检查**：`render_frame` 抽帧看画面，`export` 后读 `offlineMedia`。
5. **交付**：工程文件 + 产物 + 一句话说明改了什么。

## 短视频口播

- 结构：主轨画面 → 字幕轨 → 花字/贴纸 → 背景音乐。
- 粗剪：先按语义停顿切 3–5 段，再决定保留哪些；切点用 `timeline.razor`（以 `command_list` 实际 id 为准），
  删段后 `sequence_inspect` 核对片段数。
- 字幕：优先用引擎的转写能力生成字幕轨，再逐条校正时间；不要手敲整段。
- 调色：先统一曝光与白平衡，再逐段微调；**不要给每段一套参数**，拼接处会跳。

## 探店 / 旅行 Vlog

- 结构：开场钩子 → 地点 → 体验细节 → 价格/地址卡 → 收尾。
- 卡点：转场对齐音乐重拍；在重拍处切分，**不要用过场特效掩盖节奏问题**。
- 自检：静音看一遍。某段不静音也讲不清，说明画面没接住内容。

## 产品展示

- 结构：定帧开场 → 多角度 → 卖点字幕 → 细节特写 → CTA。
- 每次切换都要有新信息，不为炫技加转场。
- 字幕与花字不同时出现在同一区域；可读性优先于设计感。

## 字幕卡点

- 先读音乐真实时长（不要凭感觉），对齐起点后再切分。
- 卡点失败时先查音乐起点偏移，而不是加密切点。

## 批量成片

- 可做：**同一模板 + N 条素材**，逐条替换后入导出队列
  （`export.queue.add`，带明确 `path` 与 `preset`），轮询 `jobs.list` 到全部完成。
- 交付必须说明是"逐条独立导出"，不是原生批量变体流水线；
  任一条失败要留在清单里，不得隐藏。

## 通用检查项

- 画面：全片过一遍，重点看转场点、跳切、黑帧；用 `render_frame` 按时间点抽检。
- 声音：人声清晰度、音乐音量、爆音；**音画不同步是最常见也最容易被忽略的问题**。
- 文字：错别字、字号、是否压脸、是否出安全区。
- 导出：`offlineMedia` 必须为空；空则先修素材再谈交付。
- 交付：文件真的存在、能重新打开；不把预览截图当交付物。

## 禁止

- 不使用任何已作废的原型命令（`project.new`、`track.add`、`clip.add`、`asset.register`、
  `project.summary`、`engine_cli_run`、`timeline.split_clip`）。
- 不在面板未就绪时声称"已经剪好"——用户看不到的修改等于没做。
- 不把 `render_frame` 的截图当作成片验收证据。
